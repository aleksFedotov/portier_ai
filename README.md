# Portier AI

Фоновый сервис мини-отеля: читает почту через Gmail API, классифицирует письма через LLM (OpenAI Structured Outputs) и присылает уведомления администраторам в Telegram-группу с inline-кнопками подтверждения. Для запросов счетов формирует PDF-счёт. Включает мини-панель реестра компаний-заказчиков.

## Как это работает

1. Каждые `CHECK_INTERVAL_SECONDS` сервис опрашивает почтовый ящик через Gmail API по курсору (письма после последнего обработанного). При первом запуске — письма за последние `BACKLOG_DAYS` дней.
2. Сначала запрашиваются только заголовки, выполняется дедупликация по `Message-ID`.
3. Новые письма скачиваются, HTML очищается до текста, персональные данные (ФИО, телефоны, email) маскируются токенами `[GUEST_N]`/`[PHONE_N]`/`[EMAIL_N]`, после чего LLM классифицирует письмо (комментарий к брони, сообщение гостя, запрос счёта, отмена, оплата, отзыв и т.д.). Перед отправкой уведомления токены подставляются обратно — администраторы видят полные данные.
4. Администраторы получают уведомление в Telegram с кнопками («Записано в PMS», «Отвечено гостю», «Счет отправлен»). Нажатие фиксируется в базе с именем администратора.
5. Для писем «запрос счёта» заказчик ищется в реестре компаний (по ИНН, email-домену, названию; данные реестра в приоритете над извлечёнными LLM), формируется PDF-счёт (`data/invoices/`) и создаётся черновик письма в Gmail с PDF-вложением — администратор только проверяет и отправляет вручную. Если компания не найдена в реестре, черновик создаётся по данным из письма, а в уведомлении появляется пометка «новая компания — добавьте в реестр».
6. Метки прочитанности сервис не меняет — письма остаются нетронутыми для сотрудников.

## Чек-лист запуска

1. **Gmail API.**
   - Создайте проект в [Google Cloud Console](https://console.cloud.google.com/).
   - Включите **Gmail API** (APIs & Services → Library → Gmail API → Enable).
   - Настройте **OAuth consent screen** (тип External, достаточно имени приложения; в Test users добавьте почту отеля).
   - Создайте **OAuth 2.0 Client ID** типа **Desktop app** (APIs & Services → Credentials → Create Credentials) и скачайте JSON — сохраните как `credentials.json` в корне проекта (путь настраивается `GOOGLE_CREDENTIALS_FILE`).
2. **Первичная авторизация.** Выполните один раз на машине с браузером:
   ```bash
   python -m portier.gmail_auth
   ```
   Откроется ссылка авторизации Google — войдите в аккаунт почты отеля и подтвердите доступ (scopes: `gmail.readonly`, `gmail.compose`). Токен сохранится в `data/token.json` и дальше обновляется автоматически; при переносе в Docker достаточно скопировать этот файл (volume `./data`).
3. **Telegram-бот.** Создайте бота через [@BotFather](https://t.me/BotFather), получите токен. Добавьте бота в группу администраторов.
4. **TELEGRAM_CHAT_ID.** Узнайте ID группы (например, через [@getmyid_bot](https://t.me/getmyid_bot)); у групп он отрицательный, вида `-100...`.
5. **LLM-провайдер.** По умолчанию DeepSeek (`LLM_PROVIDER=deepseek`): ключ на platform.deepseek.com, из РФ доступен без VPN. Для OpenAI: ключ на platform.openai.com и `LLM_PROVIDER=openai` в `.env`. Ключи можно держать оба — переключение одной строкой.
6. **Реквизиты отеля.** Заполните блок `HOTEL_*` (название, ИНН/КПП, адрес, банк, р/с, к/с, БИК) — попадут в счета. Печать и факсимиле — PNG с прозрачным фоном, пути в `INVOICE_STAMP_PATH` / `INVOICE_SIGNATURE_PATH`.
7. **Конфигурация.** Скопируйте `.env.example` в `.env` и заполните все значения:
   ```bash
   cp .env.example .env
   ```
8. **Запуск:**
   ```bash
   docker compose up -d --build
   ```
9. **Проверка логов:**
   ```bash
   docker compose logs -f email-bot
   ```
   В логах должны быть строки «Gmail API: авторизация успешна» и «Найдено новых писем: N».

## Панель реестра компаний

Вместе с сервисом поднимается мини-панель (FastAPI + Jinja2): `http://<хост>:8080/companies` — список компаний, добавление, редактирование, удаление. Порт настраивается `WEB_PORT`.

При первом запуске реестр можно заполнить из файла `companies.yaml` (если он существует и таблица пуста):

```yaml
- name: ООО «Ромашка»
  inn: "7712345678"
  details: "р/с 4070281..."
  email: buh@romashka.ru
  subject_template: Счёт за проживание
```

> **Ограничение MVP:** панель не требует авторизации — рассчитана на работу в локальной сети (LAN). Не выставляйте порт наружу.

## Чат счетов и команда /invoices

Если задан `INVOICE_CHAT_ID`, уведомления `invoice_required` вместе с PDF уходят в отдельный чат (остальные — в основной). В этом чате работает команда `/invoices`: сначала фильтр «Все счета / Только неоплаченные», затем период (сегодня / 7 дней / 30 дней) — бот присылает счета PDF-файлами с отметкой оплаты в подписи. Оплата отмечается кнопкой «💰 Оплачен» в уведомлении о счёте. В других чатах команда молчит. Без `INVOICE_CHAT_ID` всё работает как раньше — в основном чате.

## Тихие часы

С 23:00 до 07:00 (локальное время сервера) бот ничего не присылает в Telegram: почтовый цикл просто пропускает опрос, а накопившиеся за ночь письма обрабатываются первым циклом после 07:00 — ничего не теряется. Окно настраивается `QUIET_HOURS_START` / `QUIET_HOURS_END` (часы 0–23; одинаковые значения — режим выключен). В Docker не забудьте `TZ=Europe/Moscow`, иначе окно съедет на UTC.

## Локальный запуск без Docker

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e .[dev]   # Windows Git Bash
.venv/Scripts/python -m pytest -v                # тесты
.venv/Scripts/python -m portier                  # запуск (нужен .env)
```

## Проверка на старой почте (бэктест)

Перед боевым запуском можно прогнать классификацию по старым письмам — без Telegram и без записи в базу:

```bash
python -m portier.backtest --days 45 --output report.html
```

Откройте `report.html` в браузере: сводка по типам, доля нераспознанных писем, ошибки LLM и таблица всех писем с подсветкой по типу. Для бэктеста `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` не нужны.

## Структура

- `src/portier/gmail_client.py` — опрос Gmail API (OAuth 2.0) и конвейер обработки
- `src/portier/gmail_auth.py` — первичная OAuth-авторизация
- `src/portier/cleaner.py` — очистка HTML писем
- `src/portier/pii.py` — маскирование персональных данных
- `src/portier/llm.py` — классификация через LLM (DeepSeek или OpenAI, выбор — `LLM_PROVIDER`)
- `src/portier/invoices.py` — генерация PDF-счетов (reportlab)
- `src/portier/handlers/` — шаблоны сообщений и диспетчер
- `src/portier/callbacks.py` — обработка кнопок
- `src/portier/web.py` — мини-панель реестра компаний
- `data/` — база SQLite, token.json, PDF-счета (монтируется как volume)
